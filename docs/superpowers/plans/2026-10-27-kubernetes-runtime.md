**Goal:** Complete issue #17 with Kubernetes shared workers and one-time action Jobs, preserving Docker and existing workflow authoring, qualified on the dedicated k3d cluster before support is advertised.

**Architecture:** Operator-registered targets route worker lifecycle and durable job intents through existing ports. PostgreSQL remains canonical; host mounts and host-file locks are not Kubernetes authority.

## Global Constraints

- Native Kubernetes API adapters, not an operator/custom resources; one configured Kubernetes target plus compatibility default `local-docker`.
- Kubernetes supports shared-v1 only. No legacy SQLite/local execution-file workers, no database/encryption credentials in shared workers or action Pods.
- Preserve schema-v1 `executor: docker`, `docker@1`, `docker.run@1` and exact `/flumic` file/result contract. The draft's `/factory` path is corrected against existing source.
- Docker split logs and `/tmp noexec` stay unchanged. Kubernetes combined logs, writable/executable scratch and unavailable output after a hard deadline were approved explicitly; expose those differences.
- One Deployment/one replica per worker identity, Recreate rollout; add distinct workers to scale. No automatic migration/restart of existing services.
- No ambient kube context, disabled TLS verification, project-provided kubeconfig, cluster-admin credential forwarding, hostPath/socket/host networking/PID/IPC or privileged action Pods.
- Pin target revision, namespace UIDs, resource UID/spec and absolute deadline. Lost replies never authorize a second observed effect. Unknown identity/evidence fails closed.
- Qualified CNI/default-deny and operator-qualified PID ceiling are admission prerequisites for Kubernetes container actions; reject unsupported values rather than silently ignore them.
- Capture commits before normal collector cleanup; hard deadlines/cancellation supersede retention. No completed result after the deadline and no automatic TTL of uncaptured evidence.
- Shared PostgreSQL state/claims, bounded/redacted I/O and history; per-worker private PVC is outbound spool only. Storage-dependent node-loss limits must be documented.
- Keep #17 open until real-cluster qualification, exact-head CI and merge. Never start #18 automatically. Preserve the current worktree, ignored ledger and evidence.

## Review Focus

- A target/context or namespace is replaced while effects exist: old pins must not redirect or delete another cluster's resources (Tasks 1–3, 5–6).
- A claimant loses its DB lease while a delayed Kubernetes create/unsuspend/delete finishes: stale completion must not win; cancellation tombstones must reconcile late effects (Tasks 2, 5–6).
- The action exits successfully but its collector dies, disappears or crosses the hard deadline before capture: no fabricated success or infinite collection retry (Tasks 4–6).
- Objects with matching names/labels but different UID, spec, owner or project appear during cleanup: never adopt/delete them, including credentials and PVCs (Tasks 2–5).
- The node/CNI/storage cannot enforce declared capabilities or worker identity overlaps during restart: reject unsupported admission and preserve project history/claims rather than reporting false readiness (Tasks 3, 5–8).

## File responsibilities

- `app/runtime_targets.py`: strict operator target configuration, safe snapshots/capabilities and admission.
- `app/runtime_resources.py`, `app/runtime_claims.py`: durable remote bindings and short-transaction fenced reconciliation authority.
- `app/adapters/kubernetes_api.py`: bounded SDK access, explicit auth/context, namespace UID checks, typed safe errors and separate exec client.
- `app/adapters/kubernetes_workers.py`: persistent worker manifests/lifecycle/status/PVC ownership.
- `app/adapters/kubernetes_job_manifests.py`, `app/adapters/kubernetes_jobs.py`: pure Job/payload resources and external job lifecycle/capture.
- `control-plane/kubernetes-helper/`: minimal Python init/collector protocol and image, no action-image language dependency.
- `app/runtime_router.py`: instantiate/bind target adapters behind existing worker/job ports.
- Existing broker/reconciler/API/settings/pool/database modules: pin and route target authority, settle observed lifecycle, expose scoped metadata.
- `frontend/src/features/runtime-targets.tsx`: target-aware shared worker creation/capability display; existing workers/run views consume metadata.
- `deploy/kubernetes/`, `docs/kubernetes.md`, release fixtures: installation examples, honest limits and guarded real-cluster evidence.
